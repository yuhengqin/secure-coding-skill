# 最终改动的验证约定

## 选择检查

先读目标项目的 AGENTS.md、构建配置和已有 CI。运行覆盖本次风险的已有检查，记录命令、退出状态和结果；没有工具时做静态检查并写明局限，不暗中安装依赖或把不存在的工具标为通过。

| 风险 | 有价值的验证证据 |
|---|---|
| SQL / ORM | 外部值仍作为参数传递；排序字段等结构参数经过允许列表映射 |
| 鉴权 / 对象权限 | 未登录、跨用户/租户、合法用户三个路径的实际结果 |
| 文件 / 路径 | 越界路径、绝对路径、平台分隔符、符号链接策略及合法路径的结果 |
| 模板 / DOM | 不可信内容按所需文本或受控 HTML 处理；URL与属性上下文分别验证 |
| 命令 | 固定程序及参数数组、shell 设置、参数语义与合法输入；不执行来自指南的攻击示例 |
| Go 并发 / C++ 内存 | 项目支持的并发检测、编译器诊断、sanitizer 或针对性测试；注明未运行项目 |

只在有对应风险或回归需要时增加测试；现有测试已充分覆盖的情况直接复用。

## 结果的最小结构

复杂改动可用下表；简单任务用一句话列出关键规则和验证即可，不必输出 225 条清单。

| 规则 ID | 代码位置 | 判断 | 证据／原因 |
|---|---|---|---|
| 适用 ID | 实际 file:line 或符号 | 静态符合／已运行验证／发现问题／不适用／未验证 | 读到的行为或实际命令结果 |

“已运行验证”只覆盖相应检查的断言。静态审查、工具未发现问题及测试通过，都不能证明没有其他漏洞。未覆盖业务授权、部署设置或动态路径时，明确列出相关缺口即可。

## 自动化接入

将目标项目已有的安全检查加入其 CI 必需检查；失败时阻止合并应由 CI 和仓库规则实现。Skill 提示和模型自检不能实现这种强制阻断。

本包的校验命令可直接作为任意 CI 的步骤（已有 Python 环境）：

```sh
python .agents/skills/secure-coding/scripts/guide.py check
python -B -m unittest discover -s .agents/skills/secure-coding/tests -p test_guide.py -v
```

它们验证规则包的来源、完整性和检索行为，不扫描业务代码。本次未指定业务项目或 CI，因此不预设语言扫描器、安装依赖或声称已经配置业务合并门禁。
